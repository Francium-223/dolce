# 待办

> **计划性待办**的唯一入口：还要做什么、按什么顺序、判据是什么。
> 具体曲目的版面/语义问题另记在本地私有仓库的遗留问题清单（不入库，修掉一条删一条）。
>
> 每条都写了**怎么验**——没有验法的待办等于没有待办。

## 1. 五格式原生编辑的剩余

`.pu` / `.jpwabc` / `.123` / `.abc` / `.musicxml` 五种格式都已原生打开、编辑、存回原格式，外加文本 ↔ 谱面的双向定位。
各格式的排版、试听、导出都从唯一的模型 `ScoreDoc` 出（分工见 [模块/模型-scoredoc.md](模块/模型-scoredoc.md)）。

### 1.1 已知的表达限制

- 123 那一档的**拉丁歌词**仍是连写（`AbcFamilyEmitter.lyricSeparator` 为空串）。
  中文语料碰不到；要改得连 `parseLyricLine` 一起看，否则往返会多出音节。
  **验**：`abc-roundtrip.mjs` 加一份英文歌词夹具，往返音节数不变。
- `.musicxml` 的**简谱展开档不画小节线**：MusicXML 形状投成简谱行（`pu/slots.ts::docView` 经 `jianpuproject.ts`）后，
  行里没有普通小节线元素，`jianpuInputOfDoc` 按小节线切小节，整行并成一两个大小节，谱面只在双线/终止线处有线
  （原样档的原样文档布局按模型小节画，不受影响；123/ABC 来源写出了 `|`，也不受影响）。曲中转调因此只在恰好落在
  这类小节线上时才画得出来。
  **验**：`jianpu-svg-dump --only=xml` 的差异逐份看是补出小节线；`page-check` 与 `pptx-check` 不回退。
- 123 的「每页行数」设置面板没有这一档：格式里是 `I:linesperpage`，面板等排版直通那一轮再接。
  **验**：面板改每页行数后 123 原样档分页随之变，存盘写回 `I:linesperpage`。
- 文本谱/123/ABC 的**试听不认曲中转调**：`model/playsong.ts::songMeasures` 全曲只用头部调号推音高（谱面已按模型小节画出转调）。
  **验**：一份曲中 `1=G → 1=D` 的 123 夹具，`play-check` 转调后的音高按新调算。

| R6 | `.jpwabc` 两条既有缺陷（`{C:…}` 污染解析 / `::` 抛错） | 568 首语料实测**均 0 例**，故优先级低 | 各加一份夹具，解析不抛错、音符不多不少 |

## 3.1 可视化编辑的后续

谱面上直接改谱已覆盖四种文本格式（[模块/可视化编辑.md](模块/可视化编辑.md)）。还没做的：

- **歌词录入：文本谱、`.jpwabc` 的空格**：现在这两种只能改已有字的音；没配字的音要按 `C:` 行 / `.Words` 锚点的写法补字（123、ABC、MusicXML 已能补）。
  **验**：两种格式各一份夹具，录入一段词后重新解析，`docView` 的 `syllableOwner` 对位与期望一致；撤销逐字还原。

### 3.1.1 打谱与识谱的后续（对照其它软件列出、本轮不做）

- **MIDI 键盘 / 屏幕钢琴输入**（Web MIDI）：插入模式下按琴键插音，音高按调号拼写成唱名。
- **属性检查器**：选中元素的符干方向、可见、颜色、偏移；拖动微调版面（小节宽、谱表间距）。
- **横向连续视图**：编辑时不分页、一行到底。
- **识别纠错样本导出**：核对时改过的音连同原图片段存成样本，给符号分类器攒训练数据。
- **整本批量识别进编辑器**（与成书 R3 一起）。
- **透视校正**：手机斜拍的谱先拉正再识别。

### 3.2 识别核对的后续

- **可疑项标黄**：核对视图里给把握不大的音、歌词字标黄，与拍数不对的小节一起进「下一处」。
  **2026-10-01 量过、不能拿数字格的 OCR 分数做**：识别完另跑一遍数字格打分、按第一名与第二名的差距标黄，在 testdata 单声部 GT 曲目上
  （6461 个音、真错 7 个）差距阈值 0.4 标 34 个、真错 0 个，0.5 标 52 个、真错 1 个。真错里 5 个是**八度点**、2 个是**多认出来的音**、
  只有 1 个是数字本身——数字格的把握度跟真错几乎不相关。信号要从识别主干的几何判据里带出来：八度点的大小与离数字的距离贴着阈值、
  「该不该成音」的块（宽高、与邻音间距）贴着阈值，在 `omr/jianpu.ts` 里随 `JpNum` 记一个余量，再按同样的口径量。
  **验**：measure-all 各档不降；GT 曲目上标黄的音里真错的比例（查准）与真错被标黄的比例（查全）都比上面这组高。

## 4. 上游限制（不是 123 的账，但影响迁移质量）

## 6. 识别（五线谱符号）

- **五线谱符号分类器**：位图五线谱现在靠页内自举的形状字典与几何判据认谱号、升降号、符头、符尾、segno/coda 等。
  现成的开源模型许可、类别或输入尺寸都不合用（缺 segno/coda/速度记号、或许可不明）。方向：拿公开的乐谱符号数据集训一个小的
  裁块分类器转 onnx，用本地位图五线谱 GT 微调。
  **验**：位图五线谱 GT 音符率不降（当前读数见 [现状与待办](实现/位图五线谱识别/现状与待办.md)），另报各符号类的查准/查全。

逐首剩余（小节数、拍号、时值、音符未到 90% 的曲目）见

### 6.2 矢量五线谱（文字层完整的 PDF）的剩余

判据全录见 [实现/五线谱矢量识别.md](实现/五线谱矢量识别.md)，按收益排序：

1. **SATB 四部合唱（Opus 刻谱那批）小节自检 67.1%**，全书最低。剩下两类：**跨谱行的连音**（数字与那组音符不在同一行谱上）；
   **同 x 的和弦里哪个音属于哪个声部**分不开——`checkFull` 的时间列把它们并成一列、取最小时值，长音那一支的 offset 就错了。
   逐首小节数还差 9/86，多半是记谱不同（GT 与谱面拍号写法不一）。
2. **歌词剩半成**：中文配对逐字对齐后，替换、GT 有而页面没有、页面多出三类都还有（`--lyric` 看逐首）。
3. **弧线**：天花板由音符那一档定（音符序列错一个，起讫就整段错位）；另有一部分是 GT 自己没写。
4. 剩下的音符差异集中在「英文版页面配中文 GT」那几首：只印了英文版，编配与 GT 本来就有出入，不必追。

**验**：`staff-report.mjs` 全书自检与对拍基线不降，分档看时连分母与口径一起看。

## 7. 识别（简谱）

拿手工文本谱库对比（`pudb-compare.mjs`，口径与用法见 [模块/识别-简谱omr](模块/识别-简谱omr.md)「回归」）按病因归出来、还没解决的几类；
逐首曲目记在本地私有仓库的遗留清单。**验**：measure-all 基线不降，对应书的抽样该档升。

1. **选本诗歌712 歌词档**（全本 93.0）：剩手工谱段序排法与谱面不同（63）、叠句重印口径（467）、一页两调第二调手工谱重抄附段（262、329）、
   附段 OCR 漏字错位等，逐首看。
2. **四声部分组仍失败的个例**：同声部叠音（243、13、68）、下声部是逐音叠两三个数的和弦式伴奏（f31、264 前两系统、346 副歌）、
   只剩一个 `0` 的静默声部行（12）、
   系统缺行/切歪等，整页退单声部。
3. **局部多声部**：单声部谱里只有几行上下叠两声部（雅歌 379 的 Q1/Q2 两段）。分组只认整页统一的系统，下声部行现在按单声部后续行输出，
   要支持「部分系统才分声部」。
4. **粗黑翻印、三连音密排**（赞美诗歌1218，全本音符 93.4）：`7_→1_` 与脏页上减时线连点/双线的剥离已做；`6_→5_`（斜行补高裁进了线和点）
   也已修；方括号式三连音「┌3┐」与密排已认（746）。剩减时线与数字糊成一块、粗黑页上高音点丢失（107 的 1̇ 读成 1）。

## 不做

- 不合并几条排版路径为单一引擎（阈值都是拿具体曲子换来的，合并风险高于收益）；不统一三条简谱路的观感（要改只动绘制层）。
- 识别前不设「歌词语言」：只有一个文字识别模型（中英文同一个读），歌词里的中文段、拉丁段已按字形自动分开（`rasteromr/lyric.ts`、`omr/lyrics.ts`），没有可切换的东西。
- 其余已放弃的方向（IDML、扩 `.jpwabc` 语法、ABC 第三方渲染库等）见 [需求.md](需求.md) §7。
